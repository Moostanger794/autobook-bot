# AutoBook Bot

Telegram-бот для записи клиентов автомойки, детейлинга или шиномонтажа. Один экземпляр обслуживает один бизнес; название, контакты, график и услуги настраиваются без изменения кода.

## Возможности

- Услуги и цены, запись с проверкой свободного времени, личные записи и отмена.
- Администраторы: уведомления, статусы, поиск, статистика и CSV для Excel.
- Напоминания примерно за 24 и 2 часа, FastAPI с API key, Swagger.
- Ограничение PostgreSQL `EXCLUDE` запрещает пересечение активных записей даже при одновременных запросах.

## Модель вместимости

Сейчас у бизнеса **одно общее место обслуживания**: одновременно может существовать только одна активная запись. Расчёт занятости сосредоточен в `app/services/capacity.py`, а окончательную защиту от гонок обеспечивает ограничение `no_overlapping_active_bookings` в PostgreSQL. Для нескольких постов или мастеров потребуется добавить ресурс к записи, фильтровать занятость по нему и включить идентификатор ресурса в ограничение пересечения. Текущая версия не предлагает параллельные записи.

## Стек и структура

Python 3.12, aiogram 3, FastAPI, SQLAlchemy 2 async, asyncpg, PostgreSQL, Alembic, pytest, Docker Compose.

`app/bot` — диалоги и клавиатуры; `app/services` — расписание, записи, уведомления, экспорт; `app/database` — модели и сессии; `app/api` — HTTP; `alembic` — миграции; `tests` — проверки.

## Запуск

1. В Telegram откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` и скопируйте токен.
2. Узнайте свой числовой Telegram ID через [@userinfobot](https://t.me/userinfobot) или аналогичного бота. Для нескольких администраторов укажите ID через запятую.
3. Создайте `.env`:

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `ADMIN_IDS`, `POSTGRES_PASSWORD`, `API_KEY`. В `DATABASE_URL` укажите тот же пароль и хост `postgres`, например `postgresql+asyncpg://autobook:YOUR_PASSWORD@postgres:5432/autobook`. Если пароль содержит специальные символы URL, закодируйте их. Измените бизнес контакты и график до первого запуска. Переменные `WORK_DAYS` используют Python дни недели: понедельник `0`, воскресенье `6`.

```bash
docker compose up --build
```

При запуске контейнер `init` сам выполняет `alembic upgrade head` и идемпотентный seed. Бот начинает polling, API доступно на http://localhost:8000, Swagger — http://localhost:8000/docs, health — http://localhost:8000/health. Чтобы вручную повторить миграции или seed:

```bash
docker compose run --rm init alembic upgrade head
docker compose run --rm init python -m app.scripts.seed
```

Для API списка записей передавайте заголовок `X-API-Key: <API_KEY>`. В Swagger используйте поле заголовка для `/api/bookings`.

После первоначального seed настройки бизнеса и услуги хранятся в БД. Изменение `.env` само по себе не заменяет уже созданные значения; редактируйте `business_settings` и `services` в БД или разворачивайте новую БД для нового клиента. Один запуск проекта предназначен для одного бизнеса.

В `/admin → 🛠 Услуги` можно включать и выключать услуги, менять цену и длительность, добавлять новые. Изменение длительности влияет на новые записи; время уже созданных записей сохраняется.

## Локальные тесты

```bash
python -m venv .venv
pip install -r requirements-dev.txt
python -m pytest -q
ruff check app tests
```

Интеграционные тесты PostgreSQL запускаются при `TEST_DATABASE_URL=postgresql+asyncpg://...` с отдельной тестовой БД. Они создают и удаляют схему `autobook_test`, поэтому не указывайте рабочую БД.

## Напоминания

Напоминание резервируется в PostgreSQL на две минуты. После успешного ответа Telegram сохраняется `sent=True`; при ошибке резервирование снимается и следующая проверка повторяет отправку (проверка идёт каждые пять минут). Одновременные процессы не отправляют одно напоминание параллельно. Если процесс остановится после принятия сообщения Telegram, но до записи подтверждения в БД, Telegram не предоставляет ключ идемпотентности и возможна повторная отправка после истечения резервирования.
